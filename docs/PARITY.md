# Parity with Qlib — how it is achieved and verified

The goal is **name-for-name, value-for-value parity** with Qlib's current
`main` branch (2026-08-12). "Parity" means: given the same bars, every one of
the 158 `Alpha158.factors` produces the same series Qlib's expression engine
would produce.

## Sources pinned

| Qlib file | Role |
|-----------|------|
| `qlib/contrib/data/loader.py` | `Alpha158DL.get_feature_config` — the 158 names + expressions (the contract) |
| `qlib/data/ops.py` | Operator semantics (`Ref`, rolling with `min_periods = 1`, `Greater`/`Less`, `Corr` nullification) |
| `qlib/data/_libs/rolling.pyx` | Cython `Slope` / `Rsquare` / `Resi` (ported literally, not re-derived) |

## How parity is enforced

1. **Literal port, not re-derivation.** The Cython `rolling.pyx` incremental
   algorithms were transcribed line-for-line into `Ops.scala` (same running
   sums, same `na_count` semantics, same `Resi` fit at the newest slot). Where
   a direct formula was used instead (slope = `(NΣxy − ΣxΣy)/(NΣx² − (Σx)²)`),
   it was checked against the literal port.

2. **Golden fixtures.** `src/test/resources/goldens.json` holds a deterministic
   80-bar synthetic dataset plus the expected values of all 158 features,
   generated by a script that:
   - replicates `Alpha158DL`'s default config and every `ops.py` operator with
     **pandas 3.0.5 / numpy 2.5.2** (the same library calls Qlib makes), and
   - ports the Cython `rolling.pyx` literally in Python as a cross-check.
   `Alpha158Spec` then compares the Scala output for all 158 × 80 values
   (tolerance `1e-6 + 1e-5·|v|`, `NaN`-aware). The generator script lives
   outside the repository (OS temp) — the project itself is pure Scala; the
   fixture is test data.

3. **Operator unit tests.** `ExprSpec` pins each operator's semantics
   (min_periods=1 emission, ddof=1 std, IEEE division, boolean coercion,
   `Ref(0)` broadcast, rank/quantile/idxmax/idxmin, slope/resi/rsquare on a
   linear series, corr self/negation, `lookback` values).

## Regenerating the fixture

The generator was run once from `/var/folders/.../opencode/qlib-goldens/`
(`generate_goldens.py`, venv at `qlib-goldens/.venv` with pandas 3.0.5 +
numpy 2.5.2). To regenerate after an upstream Qlib change:

1. Re-fetch `qlib/contrib/data/loader.py`, `qlib/data/ops.py`,
   `qlib/data/_libs/rolling.pyx` from `microsoft/qlib` `main`.
2. Diff the generator against any expression/operator changes; update.
3. Run it from the project root to overwrite `src/test/resources/goldens.json`.
4. `sbt test` — any mismatch is a parity regression.

## Known intentional deviations (none for values)

The library adds `Factor.polarity: Option[Polarity]` (a downstream hint, default
`None`) and a handful of convenience nodes (`Neg`, `Max2`, `Min2`, `Count`)
not used by the 158 features. None of these affect the 158 feature values.
